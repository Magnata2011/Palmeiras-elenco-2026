O QUE FOI CORRIGIDO/ALTERADO:

1) LOGIN DO ADMIN ("usuário ou senha incorretos")
   Em app.py, agora o usuário e a senha das variáveis de ambiente
   (ADMIN_USUARIO_1/2, ADMIN_SENHA_1/2) e a senha digitada no
   formulário passam por um "trim" (remoção de espaços/quebras de
   linha nas pontas). Isso é uma causa muito comum: ao colar a
   senha no painel do Render, às vezes sobra um espaço ou quebra de
   linha no fim, e a senha nunca bate.
   Depois de publicar este app.py, revise no Render (Environment):
   apague e recadastre ADMIN_USUARIO_1, ADMIN_SENHA_1,
   ADMIN_USUARIO_2, ADMIN_SENHA_2 (sem espaços antes/depois) e
   reinicie o serviço (Manual Deploy). Se quiser testar rápido, as
   credenciais padrão continuam sendo admin / admin123 e

2) PAGAMENTO: comprovante removido, vai direto pro Google Forms
   Encontrei o motivo real do fluxo estar quebrado: seu app.py já
   tinha sido atualizado (numa sessão anterior) para um endpoint

   marca a compra como paga e libera 24h para o admin conferir no

   chamando a rota antiga /api/comprovante, que nem existe mais no

   Corrigi:

6) GRADE DE NÚMEROS (style.css) — bug real encontrado
   A regra .grade-numeros estava com "display: solid;", que não é
   um valor válido de CSS — o navegador simplesmente ignorava essa
   linha, e a grade de 1000 números nunca virava um grid de verdade
   (os botões só se organizavam no fluxo normal da página).
   Corrigi para "display: grid;". Só que, ao virar um grid de
   verdade, apareceu um segundo problema que estava escondido: a
   regra pedia 50 colunas de no mínimo 100px cada (5000px de
   largura mínima — não cabe em nenhuma tela). Troquei
   "repeat(50, minmax(100px, 1fr))" por
   "repeat(auto-fill, minmax(100px, 1fr))", que mantém o mesmo
   tamanho mínimo de botão mas deixa o navegador calcular quantas
   colunas cabem, sem estourar a largura da página.

7) Admin.js — verificação sobre "expirar"
   Revisei o arquivo procurando por bugs de expiração. Não achei

   responde 401 e o painel manda a pessoa de volta pro login) e o
   rótulo "Expirada" para compras cujo prazo de pagamento estourou
   — ambos batem com o que o backend já faz. Também já estava
   ajustado pra não tentar abrir/baixar arquivo de comprovante (já
   que isso não existe mais nesse fluxo). Não precisei mudar nada
   nele; incluí no zip só pra manter o pacote completo.

8) LOGIN DO ADMIN AINDA FALHANDO — investigação adicional
   O código de app.py já estava corrigido (usuário e senha
   "trimados" nos dois lados). Se continua dando "Usuário ou senha
   incorretos" mesmo assim, o motivo quase certo é um destes dois:

   a) O app.py novo ainda não foi publicado no Render. O Render só
      atualiza o backend quando você dá "git push" com este arquivo
      E o serviço termina de reimplantar (isso aparece como "Deploy
      live" no painel do Render, pode levar 1-2 minutos).

   b) As variáveis ADMIN_USUARIO_1/2 e ADMIN_SENHA_1/2 cadastradas
      no Render são diferentes do que você está digitando no site.

   Pra descobrir qual é o caso, adicionei um log de diagnóstico: a
   cada tentativa de login que falhar, o Render vai imprimir nos
   "Logs" do serviço (painel do Render → aba Logs) uma linha assim:

       [login admin] Tentativa falhou. Usuário recebido: 'admin'
       | Usuários cadastrados no momento: ['jmagno2011', 'admin']

   Esse log NUNCA mostra a senha (nem a digitada, nem a certa) —
   só o nome de usuário digitado e quais usuários estão realmente
   cadastrados naquele momento no servidor. Depois de subir este
   app.py e esperar o deploy terminar:
   1. Tente logar de novo (pode usar qualquer usuário/senha, até
      errado de propósito, só pra gerar o log).
   2. Abra os Logs no Render e procure essa linha.
   3. Se o "usuário recebido" não aparecer na lista de "usuários
      cadastrados", o nome que você está digitando está diferente
      do que está no Render (espaço, maiúscula/minúscula trocada,
      etc.) — corrija um dos dois.
   4. Se o usuário aparecer certinho na lista mas mesmo assim falha,
      o problema é a senha — revise ADMIN_SENHA_1/2 no Render.
